# 輪講ノート

Node.js 24 で `npm ci`、`npm run dev` を実行し、表示された localhost の URL を開きます。

資料一覧で開いた PDF とページごとの付箋はブラウザーの IndexedDB に保存します。同じ PDF は内容のハッシュで識別します。最後に開いた資料とページを次回復元します。保存先はブラウザーとオリジンごとに独立しています。

## 2端末で資料を共有する

1. 2端末を同じ信頼できるネットワークにつなぎます。サーバーを動かすPCで `npm run build`、`npm run preview -- --host 0.0.0.0` を実行します。
2. 発表者は Vite が `Network` に表示した LAN アドレス（例 `http://192.168.1.10:4173`）でアプリを開き、3ページ以上のPDFを開いて「会を作成」を押します。共有できるPDFは64 MBまでです。
3. 参加者は「参加URL」を別端末で開きます。発表者が「次へ」で3ページ目に進み、参加者の画面も自動で3ページ目に切り替わることを確認します。通常は1秒程度です。
4. 3ページ目で発表者と参加者が異なる内容の付箋を1件ずつ保存し、両端末に2件とも表示されることを確認します。両端末で再読み込みし、3ページ目と2件の付箋が復元されることを確認します。
5. 参加者は会を開いたまま Wi-Fi を切り、確認用の付箋を1回だけ保存します。切断中は発表者の画面に付箋が追加されず、Wi-Fi を戻すと自動で再送されて両端末に1件だけ追加されることを確認します。

会のPDF、ページ切替履歴（ページ番号・サーバーのUTC時刻）、会で保存した付箋は `.rooms/rooms.sqlite` に保存されます。参加URLを知っている端末は、サーバー稼働中にその会のPDFを閲覧し、ページごとの付箋を読み書きできます。発表者の操作権限は会を作ったブラウザーのタブにあり、そのタブを再読み込みしても復元されます。

会の付箋は1件4000文字までです。通信が途切れた場合は、送信待ちの付箋がブラウザーに残ります。同じ会を開いていると、接続の回復後に自動で再送されます。

## テスト

Node.js 24 で `npm ci` を実行します。APIテストは `npm test` で実行できます。

ブラウザーE2Eテストは、初回に `npx playwright install chromium` で Chromium をインストールしてから `npm run test:e2e` で実行します。共有APIの遮断中に保存した付箋が再読み込み後も IndexedDB に残り、通信が戻ると同じIDで自動再送されることを確認します。サーバーが保存した直後に成功応答が失われた場合も、同じIDで再送されることを確認します。いずれの場合も、送信側と別のブラウザーで同じ会に参加した利用者の画面に付箋が1件ずつ表示され、共有APIにも1件だけ残ることを検証します。
